Before connecting the ESP32

1 · Power orderPower the buck ALONE, confirm a multimeter reads 5.00 V at OUT, then connect the ESP32, relay and sensors.
2 · No dual supplyNever have USB and the buck 5 V on the ESP32 at the same time — unplug the VIN wire when flashing over USB.
3 · Cell polaritySeries joint: cell A (+) → cell B (−). Pack + = cell B (+), pack − = cell A (−). Check twice.
4 · First bootSerial Monitor (115200) should reach "Firebase login OK". Green LED on. Buzzer and relay silent at rest.
What changed vs the 2026-11-16 draft (6 fixes, all to match the firmware): ① ultrasonic TRIG 4→5 ② ECHO 34→18 (divider kept) ③ L298N ENA 25→32 ④ IN1 26→25, IN2 27→26, IN3 32→27, IN4 33→14 ⑤ buzzer is a GPIO module on GPIO4, not relay-switched ⑥ second (red) LED removed — GPIO18 is the ECHO line. Relay (23), MPU (21/22) and ENB (13) were already correct.

4. Assembly and bring-up checklist

MATCHES CURRENT FIRMWARE
Do it in this order so a mistake only costs you one part. All control happens from the operator dashboard — this firmware build has no serial debug keys and no local web page.
A Bench build first (no chassis) — ESP32 on the project board; wire MPU6050, HC-SR04 (with divider), LED, relay, buzzer. Power only from USB (VIN wire unconnected).
B Flash — Arduino IDE → board "ESP32 Dev Module" → right COM port → Tools → Upload Speed = 115200 (mandatory, or the upload stalls) → Verify → Upload.
C Boot check — Serial Monitor at 115200. Expect, in order: "WiFi OK … IP:", "DNS OK …", "NTP: time OK", "MPU6050 OK" (or "MPU6050 NOT FOUND — IMU disabled (crash detection off)" if the sensor isn't wired — everything else still runs), then "Firebase login OK (as bus_01@device.local)". Green LED on.
D Dashboard — open the tracking web app: bus_01 shows Online, obstacle distance updates as you wave your hand at the HC-SR04. Position/speed come from the OpenCV tracker on the PC (separate, same device account).
E Power with no load — build the 2S pack + switch + buck; set the buck to 5.00 V with a multimeter; unplug USB; buck 5 V → ESP32 VIN; flip the switch. Serial must show the same clean boot as step C.
F Motors (wheels off the ground) — wire the L298N; battery rail goes through the relay (COM/NO per page 2). Use the driver page on the dashboard: forward / back / left / right (driveCmd) — the car moves on command and stops. Wrong way on a side? Swap that motor's two leads.
G Force-stop — press Force Stop on the dashboard: relay clicks, buzzer beeps, motors stop, telemetry shows force_stopped. Release: relay off, buzzer silent, drive works again.
H Crash detection — tap the car hard: the crash badge appears on the dashboard (threshold CRASH_G = 2.5 g in code). Press "Clear crash" → badge clears (the clearCrash command is consumed by the bus). If the badge flickers on gentle taps, raise CRASH_G a little.
I Mount on the chassis — MPU6050 flat and rigid near the centre, X arrow forward; ultrasonic at the front; battery low and central; loom tied down away from the wheel paths.
Note on the old draft (2026-11-16): its steps C/F/H referenced serial keys (i, w/x/a/d, b, r) and http://bus-car.local/status — those belonged to an earlier firmware draft and do not exist in the current build. Every test above is driven from the dashboard instead.
Safety — Li-ion cells can catch fire if shorted or over-discharged: keep the switch, add a 2S BMS if you can, stop discharging at ~7.0 V pack voltage, never charge unattended, and never ride the car with loose cells.
